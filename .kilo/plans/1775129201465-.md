# Fix: Admin Dashboard "Failed to load statistics"

## Root Cause

Two problems:

1. **Firestore rules not deployed** — `firestore.rules` was updated in the repo to use only `request.auth.token.admin == true`, but never deployed. The live rules on Firebase still have the old version (which used the hardcoded UID/email fallback). Since we removed the fallback from the rules file, the live rules no longer match what the code expects.

2. **Firebase CLI not installed globally** — `firebase` command is not on PATH on the user's machine. Install it with:
   ```
   npm install -g firebase-tools
   ```
   Then deploy:
   ```
   firebase deploy --only firestore:rules
   ```

## Fix 1: User must install Firebase CLI and deploy rules

```
npm install -g firebase-tools
firebase login
firebase deploy --only firestore:rules
```

Run from `C:\Users\Kids\PseudoRun`.

## Fix 2: Code change — resilient data loading in AdminDashboard

Currently `loadData()` uses `Promise.all([getStats(), getAllPrograms()])` — if either fails, everything fails and nothing shows.

Change to `Promise.allSettled` so stats and programs load independently. If one fails, show a targeted error for that section while the other still displays.

### `src/components/AdminDashboard/AdminDashboard.tsx`
- Replace `Promise.all` with `Promise.allSettled`
- Add separate `statsError: string` and `programsError: string` state (remove single shared `error` state)
- If stats result is rejected → set `statsError`, leave stats null, still show stats section with error message
- If programs result is rejected → set `programsError`, still show programs section with error message
- Remove `setLoading(false)` calls inside `loadData()` — `loading` is already handled in the `checkAdminStatus` finally block

## What NOT to change

- `firestore.rules` — already correct in repo, just needs to be deployed by the user
- `adminService.ts` — queries are correct
- Auth / ProtectedAdminRoute — working correctly
